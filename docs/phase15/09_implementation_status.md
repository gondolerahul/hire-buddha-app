| I-6 | Migration numbers 0006… instead of 08's `control_0004_cost_units` | 0004 and 0005 were taken |

### Decisions taken while building (M15.2)

| # | Decision | Why |
|---|----------|-----|
| I-17 | The lot wallet replaces the buckets in one release, behind `CreditService`'s interface; the cutover is one-way (the downgrade restores the buckets as they stood) and marks every earlier usage row settled | Running two wallets side by side would double-charge or need a reconciler; the old path had charged those rows |
| I-18 | `billing.v2_mode` is `off` or `shadow` only; the settlement charges rated rows always | There is no old path left to switch back to; the shadow row still compares the formula on the run total with Σ rows |
| I-19 | One deduct entry per billing category per settlement | The ledger then says what the money went on, per user and run (W-2) |
| I-20 | With the default tolerance 0 a wallet goes from `ok` straight to `over_tolerance` | Q1: PAYG has no tolerance; `in_debt` exists for plans that give one (T6-1) |
| I-21 | The hourly job skips rows of work that holds credit (a hold under 24 h), not only rows under 10 minutes old | A long run swept mid-way would be charged for those rows and its breaker would count them twice |
| I-22 | Money views are one middleware (and a stream filter), not a serializer in each endpoint | Every JSON answer is covered, including endpoints nobody listed; endpoints only had to add billed figures |
| I-23 | No tenant-database migration for `max_cost_usd`: `max_bill` is stored, its cost equivalent derived on save; an older cap is shown as the billed amount it stands for, and an edit that does not mention the budget keeps it | A tenant database cannot read its company's currency or formula in split mode; tenants no longer see `max_cost_usd` |
| I-24 | The flat daily amount became policies with no end (`duration_days` NULL), and per-company amounts `custom` overrides | Nobody's daily credits change at the cutover; staff set durations from the Daily credits page |
| I-25 | One wallet tick every 15 minutes runs expiry, daily grants, enforcement, notices and the checkout reaper | Local midnight comes at a different UTC time per company; one job keeps their order (expire, then grant) |
| I-26 | Suspension is enforced in `get_current_user` (402 on writes) and the Data API, with paying left open | One place every authenticated route goes through; a suspended company must still be able to pay |
| I-27 | A wallet that does not equal its ledger is an error event (`billing.wallet_ledger_mismatch`), not a gate | The check refuses nothing; it is the thing to alert on |
| I-28 | A call's hold is keyed by the call's run | `credit_holds.run_id` is the settlement's claim key; the call settles on the same run |
