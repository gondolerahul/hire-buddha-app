# WhatsApp capability walkthrough recordings

These four 1600 × 900 MP4 (H.264) recordings show the **intended HireBuddha WhatsApp experience** using the existing interactive prototype. They use sample data. The Meta handoff, permission grant, number activation, template and Flow publication, catalogue link, campaign scheduling, and message sends are simulated. Each recording carries a visible concept label and ends with the live evidence still needed.

| Recording | What the operator does | Live capture needed before Meta App Review |
| --- | --- | --- |
| [01 · Business onboarding and number control](01_business_onboarding_and_number_control.mp4) | Prepares the business, enters the Embedded Signup boundary, reviews returned assets and connection checks, then views number health. | Record the real Meta-hosted signup, authorization of a test business/WABA/phone, returned assets, registration, webhook subscription, and a working send/receive check. |
| [02 · AI messaging and human handoff](02_ai_messaging_and_human_handoff.mp4) | Inspects the automation policy gates, dry-runs the flow, publishes a demo version, takes over an AI conversation, replies, and checks delivery events. | Use a test contact and real WhatsApp API/webhook events to show an approved template send, inbound reply, AI response, human takeover, operator reply, and message statuses. |
| [03 · Templates, catalogue and Flows](03_templates_catalogue_and_flows.mp4) | Validates and submits a demo template, links a sample catalogue, then tests and publishes a sample WhatsApp Flow. | Show actual template review state, permitted catalogue asset and item status, and a published Flow opened and submitted by a test customer. Request any additional permissions only for features the app actually uses. |
| [04 · Consent, campaigns and analytics](04_consent_campaigns_and_analytics.mp4) | Reviews consent evidence, records an opt-out, checks campaign eligibility and preview, schedules a demo campaign, and inspects results. | Show real opt-in/opt-out evidence, suppression at dispatch, a controlled test send, delivery/read/reply webhooks, and reconciled report values. |

These are **design review recordings, not submission-ready proof of functioning permissions**. The final App Review recordings should be made from the implemented application and the Meta test business, with each requested permission visibly exercised end to end. Use the current requirements displayed in the Meta App Review portal for the final recording format and submission fields. A video does not itself establish Tech Partner eligibility; Meta describes a separate progression from Third Party Developer to Tech Provider and then Tech Partner in its [partner program guidance](https://whatsappbusiness.com/partners/become-a-partner/).

The recordings can be regenerated from the prototype with `python docs/whatsapp/videos/generate_walkthroughs.py`. `verify_walkthroughs.py` decodes every frame and creates visual contact sheets in `_qa/`.
