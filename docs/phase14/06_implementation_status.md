With `single` (production today) any signed-in user who knew an id could read a campaign's calls and contacts, download its report, or start and stop it. Now each follows `auth.visibility`, as the agent routes do — the caller's own company, a partner's tenants, every company for an app admin — and answers 404 otherwise (`campaign_router._visible_campaign`, checked before each route's catch-all). The mobile analytics routes (a campaign's analytics, its calls, an attempt's timeline) let any partner admin read any company's: now only the companies visibility gives it (app admins unchanged; partner users still none). `tests/integration/test_campaign_ownership.py` (8; all fail without the check), `tests/integration/mobile/test_mobile_analytics.py` (+1; fails under the old rule). The mobile routes under `/mobile/campaigns/*` already checked the caller's own company.
* **Deploy order (campaign tasks):** `execute_campaign_task`, `pause_campaign_task` and `stop_campaign_task` now take `company_id=`; as for the kernel jobs, roll the workers out before the API.
* **Migration `p14_run_settlement`** adds `credit_holds.settled_at` / `billed_amount` (control); restart the workers after it (old worker code settles without the claim).
* **Meta-Agent seed scripts in split mode:** `seed_meta_agent` and `reseed_meta_agent` work in one company's tenant database — pass `--company` (re-seed: its `target_company_id`); with `single` they still cover every company.
